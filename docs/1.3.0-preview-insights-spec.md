# Decision Tree 1.3.0: Preview & Insights

Status: Implemented and verified on Joomla 5 and Joomla 6

## Purpose

Decision Tree 1.3.0 should make trees easier to build and give Pro customers a
clear way to understand whether visitors complete them.

The release has two layers:

- Free provides preview, question duplication, optional step numbering and a
  stable interaction-event API.
- Pro inherits those features and adds anonymous, first-party analytics.

Free remains limited to one tree. Pro continues to provide unlimited trees,
tree duplication and rich outcome blocks.

## Edition boundary

| Capability | Free | Pro |
| --- | --- | --- |
| Preview the current unsaved tree | Yes | Yes |
| Duplicate a question inside a tree | Yes | Yes |
| Optional frontend step number | Yes | Yes |
| Browser interaction events | Yes | Yes |
| Analytics collection | No | Yes |
| Analytics dashboard and CSV export | No | Yes |

When Pro is absent, Free must not create analytics tables, send analytics
requests or display a non-functional Analytics button.

## 1. Preview current tree

### User behaviour

- Add a `Preview` button to the tree editor toolbar.
- Preview uses the current browser editor state, including changes that have not
  been saved.
- It opens in an accessible Joomla modal and includes the current title,
  description, questions, options, Back and Reset controls.
- Preview is functional rather than a pixel-perfect copy of the site's template.
  Decision Tree's own frontend styles must be the same as on the live site.
- Closing the modal returns the administrator to the same question and scroll
  position without changing the editor state.
- Escape closes the modal and focus returns to the Preview button.
- Analytics are always disabled in preview.

### Validation

- Existing path-health validation runs before the modal opens.
- Errors prevent preview and focus the relevant question or validation message.
- Warnings do not prevent preview, so unfinished drafts can still be checked.
- An empty tree cannot be previewed.

## 2. Duplicate a question

### User behaviour

- Add a `Duplicate question` button beside Add and Delete question.
- The selected question is deep-copied and inserted immediately after the
  original in editor order.
- The copied question text receives ` (Copy)`. If that text already exists, use
  ` (Copy 2)`, ` (Copy 3)` and so on.
- Question text, answer text, destinations and outcome content are copied.
  This includes Pro rich outcome blocks when Pro is installed.
- Existing branches that point to the original question are not changed.
- Branches within the copy keep their existing destinations. A branch pointing
  to the original continues to point to the original.
- The copy receives a fresh question ID and fresh option IDs.
- The copy does not automatically become the start question.
- After duplication, the copy is selected and the question-text field receives
  focus.
- The normal path-health check runs immediately after duplication.

No confirmation is required because duplication does not remove or overwrite
content.

## 3. Optional step number

### User behaviour

- Add a `Show step number` switch to the tree editor.
- It is off by default for existing and new trees.
- When enabled, the frontend displays `Step 1`, `Step 2` and so on above each
  question.
- It does not display a total or percentage. Branches can contain different
  numbers of questions, so `Step 2 of 5` could be inaccurate.
- Back decreases the displayed step to match the active path.
- Reset returns it to Step 1.
- The step number is hidden on the final outcome.
- Changes are announced appropriately to assistive technology without causing
  every surrounding element to be re-announced.

## Tree JSON format

The optional additions use tree data version 1.1:

```json
{
  "version": "1.1",
  "start": "q1",
  "settings": {
    "show_step_number": false
  },
  "questions": {
    "q1": {
      "question_text": "What do you need help with?",
      "options": [
        {
          "id": "o1",
          "text": "Choosing a product",
          "next": "q2"
        }
      ]
    }
  }
}
```

Rules:

- `settings` is optional. Missing `show_step_number` means false.
- Option IDs are stable within their question and are not shown to users.
- Option IDs use the same safe identifier characters as question IDs.
- Option IDs must be unique within a question, but may repeat in another
  question because analytics always scopes them by question ID.
- The editor assigns missing option IDs when a legacy tree is next saved.
- Import accepts versions 1.0 and 1.1 and assigns missing IDs without changing
  branch behaviour.
- The frontend continues to render version 1.0 trees without requiring them to
  be re-saved.
- Export preserves the settings and option IDs.
- Unknown top-level, setting and option properties remain untouched so Pro and
  compatible add-ons can extend the format.

## 4. Free interaction-event API

Free emits browser `CustomEvent` events from the `.gd-decisiontree` element.
Events bubble, allowing Pro and third-party integrations to listen at document
level.

Event names:

- `decisiontree:start`
- `decisiontree:answer`
- `decisiontree:back`
- `decisiontree:reset`
- `decisiontree:complete`

Common event detail:

```json
{
  "schemaVersion": 1,
  "treeId": 12,
  "instanceId": "decisiontree-12-1",
  "runId": "a browser-generated UUID",
  "source": "component",
  "step": 2,
  "questionId": "q2",
  "questionText": "Which size do you prefer?"
}
```

Additional answer detail:

```json
{
  "optionId": "o1",
  "optionIndex": 0,
  "optionText": "Small",
  "nextQuestionId": "q3",
  "completesTree": false
}
```

Additional completion detail:

```json
{
  "optionId": "o2",
  "optionIndex": 1,
  "optionText": "Large",
  "outcomeKey": "terminal:q2:o2"
}
```

Event behaviour:

- A run ID is created in memory for each rendered tree instance.
- No cookie, local storage or cross-page visitor identifier is used.
- `start` fires after the first question has rendered.
- `answer` fires once for each answer selection, before navigation.
- `back` fires after returning to the preceding question.
- `complete` fires after the outcome has rendered.
- Backing out of an outcome and selecting a different answer remains part of the
  same run.
- Reset closes the current run, creates a fresh run ID, renders the start
  question and emits a new `start` event.
- Preview may emit the same DOM events for functional consistency, but its
  source is `preview` and Pro must never transmit them.
- Event labels are included for third-party browser integrations. The Pro
  server does not trust them and resolves its stored labels from the saved tree.

The content plugin sets source to `content`; a component/menu rendering uses
`component`; the administrator modal uses `preview`.

## 5. Pro analytics settings

Add these Pro plugin settings:

| Setting | Default | Allowed values |
| --- | --- | --- |
| Collect anonymous analytics | No | Yes / No |
| Retention period | 180 days | 30, 90, 180, 365, indefinitely |
| Exclude logged-in users | Yes | Yes / No |

Collection is deliberately opt-in. The settings explain that:

- data stays in the Joomla database;
- Decision Tree does not set an analytics cookie;
- Decision Tree does not store names, email addresses, IP addresses, user-agent
  strings, full page URLs or referrers;
- normal web-server access logs are outside the extension's control;
- the site owner remains responsible for any privacy notice required in their
  jurisdiction.

Turning collection off stops new writes immediately but does not delete existing
data. The dashboard provides an explicit deletion action.

## 6. Pro collection transport

When analytics are enabled, Pro loads a small frontend listener through the
existing `onDecisionTreePrepareFrontend` hook.

The listener:

- ignores `source: preview`;
- ignores logged-in users when the setting requires it;
- listens only to the documented Decision Tree events;
- sends a small first-party POST request to the Decision Tree component;
- uses `fetch` with `keepalive` where available;
- fails silently so analytics can never interrupt the visitor's tree;
- does not contact granthood.co.uk or any third-party service.

Free supplies a neutral interaction controller which validates the request and
dispatches a Joomla interaction event. Pro subscribes to that server event and
stores it. When Pro is disabled, its frontend listener is not loaded and the
endpoint receives no normal traffic.

Request fields:

```json
{
  "schemaVersion": 1,
  "eventId": "UUID",
  "runId": "UUID",
  "sequence": 3,
  "eventType": "answer",
  "treeId": 12,
  "source": "content",
  "step": 2,
  "questionId": "q2",
  "optionId": "o1",
  "optionIndex": 0,
  "nextQuestionId": "q3"
}
```

Server rules:

- Accept POST only and require a valid Joomla form token.
- Accept published tree IDs only.
- Allow only the documented event names and bounded scalar values.
- Resolve question, option and outcome labels from the stored tree JSON.
- Ignore a duplicate event ID.
- Limit a run to 200 accepted events.
- Reject an event whose question/option combination is not in the saved tree.
- Store server time in UTC; do not trust a client timestamp.
- A missing start event may be reconstructed from the first valid event so that
  brief network failures do not discard the whole run.
- Responses contain no visitor or reporting data.

## Pro database structure

The Pro installer owns both tables. Free does not install them.

### `#__decisiontree_analytics_runs`

| Column | Type | Purpose |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED, primary key | Internal row ID |
| `run_key` | CHAR(36), unique | Per-instance in-memory run UUID |
| `tree_id` | INT UNSIGNED, indexed | Decision tree ID |
| `tree_revision` | CHAR(64) | SHA-256 of the saved tree JSON |
| `source` | VARCHAR(16) | `component` or `content` |
| `status` | VARCHAR(16), indexed | `active`, `completed` or `reset` |
| `started_at` | DATETIME, indexed | Server start time in UTC |
| `last_activity_at` | DATETIME, indexed | Latest accepted event time |
| `completed_at` | DATETIME, nullable | Completion time |
| `current_question_id` | VARCHAR(190), nullable | Last displayed question |
| `current_question_label` | VARCHAR(255), nullable | Label snapshot for reporting |
| `outcome_key` | VARCHAR(255), nullable | Stable terminal option/result key |
| `outcome_label` | VARCHAR(255), nullable | Outcome label snapshot |
| `step_count` | SMALLINT UNSIGNED | Current completed-path length |
| `path_json` | MEDIUMTEXT, nullable | Active answer path, IDs and label snapshots only |
| `path_hash` | CHAR(64), nullable, indexed | SHA-256 of the completed path |

Recommended indexes:

- unique `run_key`
- `(tree_id, started_at)`
- `(tree_id, status, started_at)`
- `(tree_id, outcome_key)`
- `last_activity_at`
- `path_hash`

### `#__decisiontree_analytics_events`

| Column | Type | Purpose |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED, primary key | Internal row ID |
| `event_key` | CHAR(36), unique | Retry/idempotency key |
| `run_id` | BIGINT UNSIGNED, indexed | Parent analytics run |
| `tree_id` | INT UNSIGNED, indexed | Denormalised tree ID for reporting/cleanup |
| `event_type` | VARCHAR(16) | `start`, `answer`, `back`, `reset` or `complete` |
| `sequence_number` | SMALLINT UNSIGNED | Browser event order |
| `question_id` | VARCHAR(190), nullable | Question ID |
| `question_label` | VARCHAR(255), nullable | Server-resolved label snapshot |
| `option_id` | VARCHAR(190), nullable | Stable option ID |
| `option_label` | VARCHAR(255), nullable | Server-resolved label snapshot |
| `target_question_id` | VARCHAR(190), nullable | Navigation destination |
| `outcome_key` | VARCHAR(255), nullable | Terminal option/result key |
| `step_number` | SMALLINT UNSIGNED | Step at event time |
| `created_at` | DATETIME, indexed | Server event time in UTC |

Recommended indexes:

- unique `event_key`
- unique `(run_id, sequence_number)`
- `(tree_id, created_at)`
- `(tree_id, event_type, created_at)`
- `(tree_id, question_id, option_id)`

No foreign-key constraints are required. This avoids Joomla table-prefix and
extension uninstall ordering problems. Pro explicitly deletes events before runs.

## 7. Analytics dashboard

Pro adds an `Analytics` toolbar button to the Decision Trees list. Free provides
a lightweight component view shell and extension event; Pro provides the data,
scripts and visible dashboard. Direct access without Pro shows a normal
Free/Pro explanatory message rather than an error.

Filters:

- Tree: all trees or one tree
- Date: last 7, 30, 90 or 365 days, plus custom dates
- Revision: all revisions or current saved revision

Summary cards:

- Starts
- Completed runs
- Completion rate (`completed / starts`)
- Average completed-path steps

Reports:

- Outcomes: completion count and percentage by outcome
- Drop-offs: incomplete active runs whose last activity is at least 30 minutes
  old, grouped by last question
- Answers: answer selections by question and option
- Top completed paths: path label, count and percentage
- Activity by day: starts and completions

Definitions:

- A page reload creates a new run.
- Two instances of the same tree on one page create two runs.
- A reset closes the old run with status `reset` and starts a new run.
- Reset runs are included in Starts but excluded from Drop-offs.
- A run is a drop-off only when it remains active for at least 30 minutes.
- Completion rate uses runs, not clicks.
- Answer popularity counts selections. If a visitor goes Back and selects again,
  both selections are counted.
- The path report uses the final active path at completion, so choices removed
  by Back are not included.
- Saved label snapshots keep historic reports understandable after tree edits.
- Revision filtering prevents substantially different versions of a tree being
  unintentionally combined.

### Empty and unavailable states

- Analytics off: explain how to enable collection in the Pro plugin.
- No data: explain that reporting begins with future frontend visits.
- Selected range empty: offer a wider date range.
- Deleted tree data should normally be deleted with that tree. If orphaned rows
  are encountered, label them `Deleted tree #ID` and allow their deletion.

### CSV export

CSV export uses the active tree, date and revision filters. It contains one row
per anonymous run:

- tree title and ID
- source
- started and completed times
- status
- step count
- outcome label
- completed path as readable `Question: Answer` segments

Do not export run keys, event keys or internal database row IDs.

## 8. Retention and deletion

- Run retention cleanup also deletes its event rows.
- Cleanup runs at most once per day and deletes in bounded batches so a busy site
  is not locked by one large deletion.
- `Indefinitely` disables automatic cleanup.
- The dashboard provides `Delete analytics for this tree` and `Delete all
  Decision Tree analytics`, both with explicit confirmation.
- Deleting a decision tree deletes its associated Pro analytics.
- Uninstalling Pro removes its analytics tables and data but never removes
  decision trees or Free component data. The uninstall message must state this.

## 9. Compatibility and upgrade behaviour

- Free 1.3.0 must upgrade safely from 1.2.4 without rewriting saved trees.
- Pro 1.3.0 requires Free 1.3.0 or later.
- Pro analytics tables are created on install/update and are safe to create when
  empty.
- Analytics remain off after upgrading until the administrator enables them.
- Existing Free and Pro rendering remains unchanged when step numbers and
  analytics are off.
- Import/export remains compatible with 1.2.x exports.
- Pro rich outcome blocks remain intact when questions are duplicated,
  previewed, imported or exported.
- Joomla 5 and Joomla 6 are both supported.

## 10. Acceptance criteria

### Free

- Preview works with unsaved valid content and never saves or tracks it.
- Preview is blocked by errors but allowed with warnings.
- Question duplication copies standard and unknown extension data without shared
  JavaScript object references.
- Duplicate IDs are unique and all existing branch destinations are preserved.
- Legacy trees without option IDs continue to render and receive IDs on save.
- Step numbering is optional, follows Back/Reset correctly and is accessible.
- All five browser events contain the documented versioned payload.
- No Pro installation means no analytics request or analytics database table.

### Pro

- Rich outcome blocks survive preview and question duplication.
- Analytics disabled means no collection.
- Preview and excluded users are never collected.
- Valid anonymous runs, answers, completions, resets and Back navigation are
  reflected accurately in reports.
- Spoofed tree/question/option IDs and duplicate events are rejected or ignored.
- Drop-offs appear only after the 30-minute threshold.
- Filters, revision handling, CSV export, retention and explicit deletion work.
- Pro uninstall removes analytics data and leaves Free and all trees working.

## 11. Recommended implementation order

1. Extend and validate tree JSON 1.1 while preserving 1.0 compatibility.
2. Add question duplication and automated editor tests.
3. Add preview using the shared frontend renderer and verify Pro rich blocks.
4. Add step numbering and the versioned browser event API.
5. Add the neutral Free interaction controller and server extension event.
6. Add Pro settings, tables, collection listener and secure storage subscriber.
7. Add the analytics view shell, Pro dashboard, filters, deletion and CSV export.
8. Add retention cleanup, upgrade/uninstall handling and Joomla 5/6 end-to-end
   tests.

Visual canvas editing, visitor form fields, lead capture, external integrations,
AI generation, A/B testing and cross-device tracking are deliberately outside
the 1.3.0 scope.
